# Архитектура Pathlore

> Статус: основа утверждена (решения D-013…D-016, D-019 в [decisions.md](decisions.md)); детали уточняются по ходу этапов.
> Объединяет черновик от 2026-11-04 (схема базы, стек) и уточнения этапа 0 от 2026-11-08 (хостинг, поиск, оплата, деплой).

## 1. Общая схема

```
 Файлы игры (ПК Тима)
    │  распаковка в отдельную папку (UXM / Smithbox / ERDB)
    ▼
 pipelines/<game>/ ── Python: предметы, тексты, иконки, карта мира, координаты
    │  JSON в data/ (не коммитится) → загрузка в базу
    ▼
 ┌──────────────── Российский VPS (Ubuntu, Docker Compose) ─────────────────┐
 │  Caddy/nginx (HTTPS, статика, тайлы карты)                               │
 │  apps/web (Next.js): страницы, карта, API, админка, вебхуки Robokassa     │
 │  PostgreSQL + pgvector + pg_trgm: игры, сущности, метки, пользователи,    │
 │                                     прогресс, подписки, журнал поиска     │
 └───────────────┬───────────────────────────────────────────┬──────────────┘
                 │ только текст запроса + кандидаты          │ платежи, вебхуки
                 ▼ (без персональных данных)                  ▼
     Зарубежный ретранслятор ИИ                         Robokassa → чеки в «Мой налог»
     (Cloudflare Worker или мини-VPS)
                 │
                 ▼
            API ИИ-провайдера
```

Почему один VPS (D-014): одна база и один деплой дешевле и проще двух копий сайта; ПДн россиян остаются в РФ;
зарубежным пользователям российский сервер тоже доступен. Зарубежный CDN для тайлов — только если замеры покажут, что миру медленно.

## 2. Стек

| Часть | Выбор | Почему |
| --- | --- | --- |
| Веб-приложение | Next.js 16 + TypeScript (App Router, Tailwind 4) | Серверный рендер для SEO, одна кодовая база для ПК и телефона |
| Карта | Leaflet, `CRS.Simple` | Лёгкая, работает с произвольными картинками, а не только с географией |
| База | PostgreSQL + pgvector + pg_trgm | Один сервер на всё: данные, полнотекстовый, нечёткий и векторный поиск |
| Пайплайны | Python | ERDB и инструменты сообщества для Elden Ring на Python |
| ИИ | Claude через API (кандидат — Haiku 5.5) | Только выбор из найденных кандидатов и формулировка ответа; модель — по замеру (D-016) |
| Деплой | Docker Compose на российском VPS | ПДн из РФ хранятся в РФ; один сервер дешевле |
| Оплата | Robokassa | Работает с самозанятыми, подписки, автоматические чеки |

## 3. Данные (этап 1)

Источники и лицензии — [data-sources.md](data-sources.md). Технически:

- Стабильные ID сущностей = ID параметров игры → при патче пайплайн перезапускается и обновляет базу upsert-ом.
- Ручные правки (метки из админки, проверка Тима) хранятся отдельно и накладываются сверху — повторная выгрузка их не затирает.
- Координаты: локальные координаты тайла (файлы карт MSB) → мировые → пиксели карты; калибровка аффинным
  преобразованием по 5–10 известным точкам на каждый слой.
- Карта мира: текстуры карты из игры → склейка → пирамида тайлов для Leaflet; слои: поверхность, подземелья, Земли Тени (DLC).
- Тексты: названия и описания на всех языках из локализации игры (RU и EN — в MVP).

## 5. Умный поиск (D-015)

Гибридный, ИИ не выдумывает ответы:

1. **Нормализация запроса.** Опечатки и транслит (pg_trgm), синонимы и сленг игроков из словаря игры.
2. **Поиск кандидатов в базе** (быстро, без ИИ): полнотекстовый (RU/EN) + векторный (эмбеддинги описаний предметов,
   квестов, локаций) по выбранной игре → 20–30 кандидатов.
3. **ИИ-шаг** (через ретранслятор): модель получает запрос и только эти карточки, возвращает ID подходящих сущностей
   и короткое пояснение. Код отбрасывает любые ID не из списка кандидатов. Нет кандидатов — «не нашёл», без догадок.
4. **Обратная связь.** Кнопка «нашёл?» → `search_log` — главная метрика беты (цель ≥ 80%); запросы «не нашёл» видны в админке.

Бесплатно: несколько умных запросов в день (лимит на сервере); обычный поиск по названию — без ограничений.
Частые запросы кэшируются. Эмбеддинги: открытая мультиязычная модель на нашем сервере или API — решаем на этапе 2.

### Оценка стоимости ИИ-шага (прайс Anthropic на октябрь 2026 — перепроверить на этапе 0)

Допущение: ~3 000 входных токенов (инструкция + 25 карточек) и ~300 выходных на запрос.

| Модель | Цена за 1 млн токенов (вход / выход) | ≈ на запрос | ≈ на 10 000 запросов |
|---|---|---|---|
| Claude Haiku 5.5 | $0.10 / $0.50 | $0.0005 | ~$5 |
| Claude Sonnet 5.5 | $2 / $10 | $0.009 | ~$90 |
| Claude Opus 5.5 | $4 / $20 | $0.018 | ~$180 |

Кэширование неизменной инструкции снижает стоимость входа. В бюджете плана на ИИ — 0–3 000 ₽ за 4 месяца;
модель выбираем замером качества на 100–200 реальных запросах (D-016), решение за Тимом.

## 6. Аккаунты и синхронизация

- Вход: e-mail (ссылка или пароль) в MVP; VK ID / Яндекс ID — кандидаты после запуска.
- Прогресс сначала сохраняется в браузере (работает без аккаунта и офлайн), при входе синхронизируется с сервером;
  конфликты — по времени отметки. Синхронизация ПК↔телефон — функция Pro.

## 7. Оплата (этап 4)

- Robokassa: разовые платежи (год, пожизненный) и рекуррентные (месяц) — условия рекуррентов уточнить при подключении.
- Сервер принимает уведомление об оплате (проверка подписи), продлевает подписку; чек в «Мой налог» создаёт Robokassa.
- Счётчик пожизненных: продажа закрывается автоматически на 500-й.
- Страницы: тарифы, оферта, политика конфиденциальности, атрибуция CC BY-SA — нужны до модерации Robokassa.

## 8. SEO и языки

- Отдельная страница на каждый предмет, квест, босса, сет — `/ru/...` и `/en/...`, с `hreflang`, `sitemap.xml`,
  структурированными данными; страницы генерируются из базы.
- Яндекс Вебмастер и Google Search Console — подключить на этапе 4.

## 9. Админка (для Тима)

Перетаскивание меток на карте, отметка «проверено в игре», правка текстов, список запросов «не нашёл».
Доступ только по роли администратора.

## 10. Деплой

- Сборка в GitHub Actions (у VPS мало памяти для сборки Next.js) → образ Docker → деплой на VPS по SSH.
- Ежедневный `pg_dump` в российское объектное хранилище.
- Секреты — в переменных окружения на сервере и в секретах GitHub; их заводит Тим.

## 11. Открытые вопросы

3. Пересчёт координат — калибровка по 5–10 точкам на слой (этап 1).
4. Доступность из РФ хостинга и ИИ-API: проверка с российского VPS и человеком в России (этап 0);
   условия ИИ-провайдера для конечных пользователей из РФ.
5. Эмбеддинги: своя модель или API (этап 2).
6. Нужен ли зарубежный CDN для тайлов карты — по замерам после беты.
