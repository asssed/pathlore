# Архитектура — черновик этапа 0

> Статус: основа утверждена 2026-11-08 (решения D-013…D-016 в [decisions.md](decisions.md)); детали уточняются по ходу этапов.
> Стек зафиксирован планом: Next.js, Leaflet, Postgres + векторный поиск, Robokassa. Здесь — как это собрать.

## 1. Общая схема

```
 Игрок (ПК / телефон)
        │ HTTPS
        ▼
 ┌──────────────── Российский VPS (Ubuntu, Docker Compose) ─────────────────┐
 │  Caddy/nginx (HTTPS, статика, тайлы карты)                               │
 │  Next.js (apps/web): страницы, карта, API, админка, вебхуки Robokassa     │
 │  PostgreSQL + pgvector + pg_trgm: игры, сущности, метки, пользователи,    │
 │                                     прогресс, подписки, журнал поиска     │
 └───────────────┬───────────────────────────────────────────┬──────────────┘
                 │ только текст запроса + кандидаты          │ платежи, вебхуки
                 ▼ (без персональных данных)                  ▼
     Зарубежный ретранслятор ИИ                         Robokassa → чеки в «Мой налог»
     (Cloudflare Worker или мини-VPS)
                 │
                 ▼
            API ИИ-провайдера

 ПК Тима: игра → pipeline/ (Python) → data/*.json → импорт в Postgres (без файлов игры)
```

Почему один VPS (D-014): одна база и один деплой дешевле и проще двух копий сайта; ПДн россиян остаются в РФ;
зарубежным пользователям российский сервер тоже доступен. Зарубежный CDN для тайлов карты — только если замеры
покажут, что миру медленно.

## 2. Репозиторий (D-013)

```
apps/web/        Next.js (App Router, TypeScript): сайт, карта, API, админка
pipeline/        Python: выгрузка ERDB/Smithbox, пересчёт координат, тайлы карты, импорт
db/              схема и миграции SQL
data/<game>/     обработанные факты (JSON) — то, что импортируется в базу
docs/            план, решения, этапы, архитектура
```

## 3. Данные (этап 1)

| Что | Откуда | Как |
|---|---|---|
| Предметы, статы, иконки | ERDB (MIT) по файлам игры | JSON → `data/elden-ring/items*.json`; стабильные ID = ID параметров игры |
| Тексты на всех языках | Smithbox (FMG) | названия/описания по локалям; RU и EN — в MVP, остальные — после запуска |
| Координаты | файлы карт игры (MSB) | локальные координаты тайла → мировые → пиксели карты; калибровка аффинным преобразованием по 5–10 известным точкам на каждый слой |
| Карта мира | текстуры карты из игры | склейка → пирамида тайлов для Leaflet (`CRS.Simple`); слои: поверхность, подземелья, Земли Тени (DLC) |
| Квесты, лор | Eldenpedia (CC BY-SA 4.0) | вручную связываем шаги с метками; у каждой записи — источник и лицензия для атрибуции |
| Ачивки | Steam | публичный список достижений |

Правила: файлы игры остаются на ПК Тима вне репозитория; конвейер повторяем — при патче игры перезапускается и
обновляет базу «upsert»-ом по стабильным ID, не теряя ручных правок (ручные правки хранятся отдельно и накладываются сверху).

## 4. База (набросок)

- `games`, `map_layers` (слой карты, размеры, параметры калибровки)
- `entities` (тип: item / npc / boss / grace / location / secret…, игровой ID, категория, статы JSONB)
- `entity_i18n` (entity, locale, name, description, slug) — официальные названия из локализации игры
- `markers` (entity, layer, x, y, источник, `verified_at`, `verified_by`) — метка = точка на карте
- `quests`, `quest_steps` (шаг ↔ метки), `builds`, `fashion_sets` (части ↔ сущности), `achievements`, `mechanics`
- `sources` (url, лицензия, автор) — для страницы атрибуции CC BY-SA
- `search_index` (сущность, локаль, текст для поиска, `tsvector`, эмбеддинг `vector`)
- `users`, `sessions`, `progress` (user, marker/quest_step, когда отмечено), `subscriptions`, `payments`
- `search_log` (запрос, что показали, кнопка «нашёл?») — главная метрика беты

## 5. Умный поиск (D-015)

1. **Извлечение кандидатов в базе** (быстро, дёшево, без ИИ): полнотекст (`tsvector`, RU/EN) + опечатки и транслит
   (`pg_trgm`) + смысловая близость (pgvector) → 20–30 кандидатов.
2. **ИИ-шаг** (через ретранслятор): получает запрос и только эти карточки, возвращает ID подходящих сущностей и
   короткое пояснение. Ответ проверяется кодом: любые ID не из списка кандидатов отбрасываются.
3. Нет кандидатов или ИИ ничего не выбрал → «не нашёл» + обычные результаты поиска.
4. Частые запросы кэшируются; лимит бесплатных запросов в день — на сервере.

Эмбеддинги: модель выбираем на этапе 2 — открытая мультиязычная модель на нашем сервере (без внешних зависимостей)
или API-провайдер; критерий — качество на русских запросах и цена.

### Оценка стоимости ИИ-шага (прайс Anthropic на октябрь 2026 — перепроверить на этапе 0)

Допущение: ~3 000 входных токенов (инструкция + 25 карточек) и ~300 выходных на запрос.

| Модель | Цена за 1 млн токенов (вход / выход) | ≈ на запрос | ≈ на 10 000 запросов |
|---|---|---|---|
| Claude Haiku 5.5 | $0.10 / $0.50 | $0.0005 | ~$5 |
| Claude Sonnet 5.5 | $2 / $10 | $0.009 | ~$90 |
| Claude Opus 5.5 | $4 / $20 | $0.018 | ~$180 |

Кэширование неизменной инструкции снижает стоимость входа. В бюджете плана на ИИ — 0–3 000 ₽ за 4 месяца,
поэтому модель выбираем замером качества на 100–200 реальных запросах (D-016); решение за Тимом.

## 6. Аккаунты и синхронизация

- Вход: e-mail (ссылка или пароль) в MVP; VK ID / Яндекс ID — кандидаты после запуска.
- Прогресс: сначала сохраняется в браузере (работает без аккаунта и офлайн), при входе — синхронизируется с сервером;
  конфликты — по времени отметки. Синхронизация ПК↔телефон — функция Pro.

## 7. Оплата (этап 4)

- Robokassa: разовые платежи (год, пожизненный) и рекуррентные (месяц) — условия рекуррентов уточнить при подключении.
- Сервер принимает уведомление об оплате (проверка подписи), продлевает подписку; чек в «Мой налог» создаёт Robokassa.
- Счётчик пожизненных: продажа закрывается автоматически на 500-й.
- Страницы: тарифы, оферта, политика конфиденциальности, атрибуция CC BY-SA — нужны до модерации Robokassa.

## 8. SEO и языки

- Отдельная страница на каждый предмет, квест, босса, сет — на `/ru/...` и `/en/...`, с `hreflang`, `sitemap.xml`,
  структурированными данными; страницы генерируются из базы (статическая сборка + обновление по расписанию).
- Яндекс Вебмастер и Google Search Console — подключить на этапе 4.

## 9. Админка (для Тима)

Перетаскивание меток на карте, отметка «проверено в игре», правка текстов, список запросов «не нашёл» —
чтобы видеть дыры в базе. Доступ только по роли администратора.

## 10. Деплой

- Сборка в GitHub Actions (у VPS мало памяти для сборки Next.js) → образ Docker → деплой на VPS по SSH.
- Ежедневный `pg_dump` с хранением в российском объектном хранилище.
- Секреты — в переменных окружения на сервере и в секретах GitHub; их заводит Тим.
- На этапе 0 проверить, что с российского VPS доступны GitHub, реестр образов и npm.
